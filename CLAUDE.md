# Oxide - проводник для Windows на Rust

## Версия приложения - обновлять ВСЕГДА

При **каждом** изменении кода приложения повышай версию. Версия хранится в одном месте:
`Исходники/Cargo.toml` → `[package] version`. В коде она берётся через `env!("CARGO_PKG_VERSION")`,
поэтому больше нигде её править не нужно

Какую цифру повышать, решай сам по смыслу изменения (схема MAJOR.MINOR.PATCH):

| Изменение | Пример | Что повышать |
| --- | --- | --- |
| Исправление ошибки, мелкая правка, оптимизация без новых возможностей | 1.0.0 → 1.0.1 | PATCH |
| Новая функция, новая тема, новый пункт меню, заметное улучшение | 1.0.1 → 1.1.0 | MINOR (PATCH сбрасывается в 0) |
| Переделка, ломающая совместимость (формат настроек, поведение по умолчанию) | 1.4.2 → 2.0.0 | MAJOR (MINOR и PATCH в 0) |

Если за одну сессию сделано несколько изменений, повышай один раз по самому крупному из них

Новую версию упоминай в отчёте пользователю и добавляй строку в `CHANGELOG.md`

## Папки

- `Исходники/` - проект Rust (Cargo). Сборка: `cargo build --release` внутри этой папки
- `Oxide/` - готовое приложение: после каждой релизной сборки копируй сюда `Исходники/target/release/oxide.exe`

## Интерфейс

Перед любой работой с интерфейсом прочитай `DESIGN.md` целиком и бери значения только оттуда
(цвета, размеры, отступы, шрифты, анимации). Коды цветов и размеры живут в `Исходники/src/theme.rs`,
DESIGN.md и theme.rs меняются вместе

Главный принцип: пользователь Проводника Windows 11 должен работать в Oxide без переучивания -
те же места кнопок, названия команд, горячие клавиши и поведение

## Стиль текста

Везде, и в приложении, и в репозитории (README, CHANGELOG, комментарии, описания релизов):

- не использовать длинное тире «—», только короткий дефис «-» или перестроить фразу
- не ставить точку в конце фраз, подписей, пунктов списка и сообщений
